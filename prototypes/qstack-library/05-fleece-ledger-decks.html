Direction notes, Pass A
  1. Ticket anatomy fused in. Every card now splits into a title zone and a metadata stub, divided by a hairline dashed rule and a notch pair colored to the surface behind the card in each view. The standing anatomy contract holds: title top-left, star cluster top-right, metadata bottom-left, status and move bottom-right. Serves locality-first, every control beside the object it affects.
  2. Seal and edge split, the central fix. The fleece foil edge now means exactly in rotation: reversible status, applied and removed live on move, and the earned shine rides with it. The gold seal means exactly 25 stars: a durable achievement that never depends on status, updating live when starring crosses 25. All four combinations exist in the dataset: s1 and s4 carry both, s3 edge only, s9 seal only after its move to ready, the rest neither. Serves two-states-not-tiers with each state carrying one exact meaning.
  3. Gold reinforces, ink carries. The star count is an ink numeral, the status is a word inside the Move-to button, the seal duplicates the ink count through its tooltip and aria-label, the fleece edge duplicates the words in rotation in the Move-to button. Gold never carries a state alone, per the contrast floor.
  4. Stage pill. Five stages rendered as differentiated pills, dot plus tinted ground plus ink text, all token-derived: phone screen, technical screen, onsite, take-home, final. No red in the stage set, no traffic-light triad. Serves legibility at a glance without a color code to memorize.
  5. Share affordance. A small pressable icon button in the stub's action corner copies a share link and confirms with the card-local pill, announced politely. Serves locality: the confirmation lands where the action happened.
  6. Arrange dropdown. A caret after the title opens a four-item menu: Move up, Move down, Move to front, Move to back. It reorders within the shelf or list in stack, list, and board views and adjusts layering on the canvas, with focus preserved and undo in the pill. Keyboard parity via the same menu grammar as Move-to.
  7. Density control. Comfortable, Compact, Dense, persisted to argo-proto-04-density-v1. Dense keeps every ink text at 11px or larger, hides the watermark and set mark, collapses chips to stage, count, and Screened, and fits five to six readable gallery columns in a 1280px window. Canvas ignores density until Pass B.
  8. Fuller preview, no clipping. The fan keeps its three scattered rows and adds a straight See all N questions footer that expands to every row, metadata only, never question text. When a fan would clip at the canvas boundary, the canvas grows temporarily and restores on close.
  9. One feedback pattern. Every confirmation is the same forest pill straddling the card's bottom edge, message and undo never separated, auto-dismiss at five seconds. Off-board cards offset their Move-to button by nine pixels past the corner, an intentional signal that the card is literally off the board.
  10. Flag tokens wired. The flagged chip on s7 uses the flag tokens for their real product meaning, a compliance flag count visible only to the author, ink text on flag-soft. The only red in the file. Dataset deltas this pass: s9 moved to ready, and stage and flagged fields added to every stack. The shine remains single-hue gold, not holographic rainbow, per the standing ban.
Direction notes, Pass B
  1. QDeck, a first-class object. A QDeck bundles every stage stack for one role into one visible unit: a data layer (stackDeckId, isLoose, libraryItems, addStackToDeck, createDeckFromStacks, removeStackFromDeck), a card (buildDeckCard, ghost layers, an explicit face panel), an unfurl interaction, and drag-to-combine on canvas. Fifteen new QStacks arrive pre-decked into five QDecks, s1 through s10 stay loose, so the library reads as fifteen top-level items with twenty-five stacks worth of stage detail one unfurl away, the concrete demonstration of legible at volume.
  2. Decks excluded from Board, deliberately. A QDeck spans every stage of a role, which means it spans every status a stage can be in, and the board is a single-status-per-card Kanban of individual stage-work. Inventing a status rollup for a deck, picking which member status wins, would be exactly the kind of deck-intelligence judgment this pass is scoped to avoid. Board renders loose stacks only; a decked stack never appears there, not even on its own.
  3. The seal rides with stars, the fleece edge does not. The seal means twenty-five stars, an achievement, and a deck has its own independent star count, so it qualifies on the same terms a stack does. The fleece edge means in rotation, a single status value, and a deck has no single status to carry it. Giving a deck the edge would either force a false status onto it or quietly redefine what the edge means; neither is on the table this pass, so decks get the seal and never the edge, and never the earned shine that rides with the edge.
  4. Unfurled member rows are informational only. Title, stage pill, status word, star count, nothing clickable, no question text (there is none at stack level to begin with, so this is not a compliance boundary, just a scope one). Moving or reordering a stack inside its deck, or dragging one out through the unfurl panel, is real product judgment about how a team wants its loop assembled; the data layer already supports a stack leaving a deck cleanly (removeStackFromDeck), but no control exposes it this pass, so it stays a read surface until that judgment is made deliberately.
  5. Deck formation and the D key are canvas only. Drag-to-combine needs two things List and Stack gallery do not have: freeform position to detect a real overlap, and a spatial "drop" gesture the confirm popover can anchor to. Building a parallel combine affordance for a flat register or a grid would be a different interaction, not a port of this one; Canvas is where two items can physically meet, so that is where combining lives, keyboard included.
  6. Copy-versus-move exists at the data layer, only move ships in this pass's UI. addStackToDeck's rule, already decked means copy with a new synthetic id, loose means a plain move, is correct today even though every path this pass builds (drag onto a target, the D key menu) always starts from a loose stack, so only the move branch ever runs. The copy branch is there for a future pass that lets a stack be dragged out of one deck into another; leaving it unbuilt now, with the rule already correct in the data layer, means that future pass changes a UI surface, not the model underneath it.
  7. Alignment hairlines, ported without the grid. Direction 03's guide-line detection is reused verbatim: two thin lines, six-pixel edge tolerance, shown during a canvas drag and hidden on release. Its snap-to-grid was deliberately left behind; the guides are a visual aid only, they never round or lock the committed drop position, freeform placement on canvas stays exactly as free as Pass A left it.
  8. Pinning is a utility, not an accomplishment. The pin toggle uses ink only, a genuine silhouette change between its two states, never gold, matching the file's own rule that gold is reserved for actions, stars, and accomplishment. A pinned card cannot be dragged or arrow-nudged, but it stays a fully valid target for something else being dragged onto it, since only its own movement is meant to freeze.
  9. The position constraint, restated. Canvas x and y remain spatial memory only, never a ranking, ordering, or scoring signal, enforced in this prototype by the fact that no sorting or arrangement logic anywhere in the file reads state.positions. When this becomes real, positions belong in their own table, readable only by the canvas renderer, and no assessment or ranking code path may ever read them, now or later.
